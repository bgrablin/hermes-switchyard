# Feature and test matrix

This matrix separates synthetic checks from host integrations and comparative evaluation.

| Area | Coverage | Evidence in this repository | Release statement |
| --- | --- | --- | --- |
| Record-triage workflow | `record_triage` batching, local bypass, abstention, malformed and late responses, partial batch failure, consumer rejection, artifact verification | `python -m unittest tests.test_record_triage -v` | Synthetic transport only. It shows plumbing and fail-closed behaviour, not Jev judgement quality or cost benefit; see [docs/RECORD-TRIAGE.md](RECORD-TRIAGE.md). |
| Native manifest | Root `plugin.yaml`, root `register(ctx)`, declared tools, config schema | `hermes plugins validate` in the pinned Hermes lane and the local portability test when the Hermes parser is installed | Admission shape is checked; it does not certify runtime task quality. |
| Offline plugin behavior | Routing, policy gates, response validation, target freshness, error redaction | `python -m unittest discover -s tests -v` | Tests use synthetic transports and dispatch fixtures. They do not call a live service. Live Chromium/external-origin browser tests stay skipped unless `SWITCHYARD_LIVE_BROWSER_TESTS=1`. |
| Synthetic evaluation | Fixture schema, policy behavior, abstention, source hashes | `python evaluation/evaluate.py --validate` | The evaluation is a deterministic policy and plumbing check, not a quality-calibration result. |
| Portability and public hygiene | Tracked-file paths, generic credential patterns, private host suffixes, stale branding, version consistency, fixture boundaries | `python scripts/check_portability.py` and `--history` | The scan is pattern-based and deliberately does not claim complete secret detection. |
| Release archive | Exact Git-blob payload allowlist, deterministic bytes, strict source SHA, embedded checksums, fresh extraction, optional external source reference | Resolve the reviewed commit with `git rev-parse --verify HEAD`, then pass that value to `python scripts/build_release.py --source-sha COMMIT_SHA`; `tests/test_release.py` checks the contract. | The ZIP excludes tests, evaluation data, CI files, caches, logs, and local evidence. `--verify` with `--source-root` and `--expected-source-sha` distinguishes source verification from internal integrity checks. |
| Linux and Windows Python matrix | Python 3.11, 3.12, and 3.13 on Linux and Windows; weekly/manual pre-qualification on Ubuntu Python 3.14 | `.github/workflows/switchyard-compatibility.yml` | Pull requests run one fast required combo (Ubuntu / Python 3.11). Pushes to `main` run the full six-job matrix. Weekly and manual runs add one non-required Ubuntu / Python 3.14 cell with `continue-on-error`; Python 3.14 is pre-qualification only until Hermes supports it, and the supported Hermes range remains `>=3.11,<3.14`. A fresh full-matrix run is required for a release claim. |
| Downloaded and installed Windows archive | Exact Ubuntu-built ZIP and outer SHA-256, Windows external Git-blob check, byte-for-byte extracted install in an isolated Hermes home, fresh pinned Windows Hermes discovery, one registered synthetic `jev_assess` call with denied socket connects | Dependent `windows-installed-archive` job in the manual `.github/workflows/release-candidate.yml`; sanitized receipt uploaded even on failure | A passing exact-head Windows job is required for this archive gate. Source-checkout matrix results, a Linux archive test, or a failed/absent Windows receipt cannot substitute for it. It does not test a user's profile, live Jev, production gateway, or real GUI behavior. |
| Toolset exposure | Registered versus callable for each tool under the default, saved-list, and explicit `--toolsets` selections, plus a registration another owner already holds, a failed availability check, a toolset named in `agent.disabled_toolsets` even under an explicit pin, and readiness tied to the configured provider's key | `tests/test_toolset_exposure.py`: deterministic stand-in cases that run everywhere, and real-loader cases that run Hermes' real CLI entry point in a disposable Hermes home and compare `hermes switchyard status --json` with Hermes' own catalog builder | The real-loader cases skip, with the reason, when no Hermes runtime can be imported; `SWITCHYARD_REQUIRE_HERMES=1` turns that skip into a failure. Set `SWITCHYARD_HERMES_ROOT` to a Hermes source checkout that has its own virtual environment when the test interpreter cannot import Hermes itself. The offline CI jobs run the suite under the interpreter that has the pinned Hermes installed, on Linux and Windows, so these cases execute there instead of skipping; a fresh CI run is required to claim that. A run on one operating system does not show behavior on another. |
| Native Hermes integration | Exact upstream Hermes commit `8503ee4459316ce092b5d69b7d396c27aa03d0be`, isolated `HERMES_HOME`, real `hermes plugins validate`, and parser call | Manual release gate in [docs/RELEASE.md](RELEASE.md) | The gate has no plugin credentials and no model call. A dependency-install failure blocks publication. |
| Real tool invocation | All seven registered handlers called through Hermes' real registry entries with synthetic HTTPS decisions and a fail-closed in-memory native-action dispatcher | `scripts/ci/check_native_tool_invocation.py`, run in the required PR compatibility check; `tests/test_native_tool_invocation.py` pins ballot validity, meaningful terminal states, negative controls, and rejection of unexpected dispatch | Proves the plugin's own handler wiring with public synthetic fixtures; it does not prove a live Jev response or real desktop action. |
| Real GUI behavior | Windows desktop execution and coordinator-owned final verification | Not covered by offline CI | Real GUI tests are pending. The plugin returns `verified: false` for completion candidates. |
| Live selector value benchmark | Real Jev provider receipts compared with the deterministic local lexical baseline on 24 frozen public-synthetic cases | `evaluation/benchmark/value_report.py`, `evaluation/benchmark/test_value_report.py`, and [BENCHMARKS.md](BENCHMARKS.md) | Supports selector-level accuracy, abstention, latency, and usage claims only; it does not prove whole-agent improvement. |

## Open evaluation work

A fair stock-Hermes computer-use comparison and a counterbalanced whole-agent study remain unmeasured. The [benchmark report](BENCHMARKS.md) records the tested arms and their limits. `jev_skill_select_many` selects several skills; it does not plan or coordinate a multi-skill workflow. Catalog admission is a separate maintainer review, not a result of repository installation or release (see [release instructions](RELEASE.md)).
