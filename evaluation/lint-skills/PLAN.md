# Offline skill-routability lint: frozen evaluation

This is a local, advisory report, not Hermes' SKILL.md standards validator. It reads only the `name` and `description` fields from the active Hermes `skills_list()` registry. It never reads bodies, supporting files, files from disk, or a live provider, and never changes skill content. Do not run it on the active private catalog without an explicit data go-ahead. The synthetic fixture is the only development input.

## Frozen contract (v1)

- Normalize description words with Unicode case folding and ASCII alphanumeric tokens. Drop exactly: `a`, `an`, `and`, `for`, `in`, `of`, `on`, `or`, `the`, `to`, `use`, `when`, `with`. Compare token **sets** with Jaccard intersection/union. Exact equality of all normalized words counts as a duplicate. Two distinct names with similarity at least **0.75** are `near_duplicate`; from **0.50** (inclusive) to below 0.75 are `confusable`. Below 0.50 is not a pair finding. This is a heuristic for description overlap, not evidence that two skills do the same job. Report connected peer groups and each member's named peers in stable name order.
- A description has `short_description` if below **40** characters, `long_description` if above **200** characters, and `missing_use_when` if it does not start with `Use when` (ASCII case-insensitive, word boundary). Thresholds are character counts, including spaces. These are routability hints, not a substitute for Hermes standards lint.
- Bound a catalog at **1024** entries, each compared description at **4096** characters and **128** distinct tokens, and names at **128** characters. Reject an oversized catalog as incomplete instead of reporting a partial success. Reject invalid registry shape; skip malformed individual rows and count them without repeating their contents. No evidence from a truncated description may be described as a full-text collision; mark it invalid/omitted if longer than the comparison cap. Accept only safe, exact skill identifiers made of ASCII letters/digits, hyphens, underscores and colons. Never export descriptions, body/content fields, supporting files, paths, or error strings. Stable JSON schema `switchyard.lint_skills.v1` and stable ordered text output; no status/receipt/config/Jev or catalog mutation.

## Frozen ground truth and kill gates

`fixture.json` carries three true collision pairs: one exact duplicate, one near duplicate, and one confusable pair, plus independent distinct entries. All non-truth pairs are negatives; any reported pair involving a distinct entry is a false positive. Oversize is generated deterministically from the fixture's `oversized` record, not expanded in source control. Its count is one past the cap. The invalid hostile row and description/body canaries must never appear in any CLI output or JSON, even on failure. The two benign description canaries also must never appear in output; a body field must not be accessed by the implementation.

Score pair-level `precision=TP/(TP+FP)` and `recall=TP/(TP+FN)` with the literal expected pair set, and report all denominators. Ship only if precision is at least **90%**, recall at least **80%**, and distinct false positives are **zero**. The reference baseline is exact duplicate matching after casefold and whitespace collapse; the heuristic must find more true collisions than this baseline without adding distinct false positives. Check text/JSON deterministic ordering and JSON round-trip. Any leakage or failed threshold kills the candidate. Fixture success alone never earns a harness SHIP verdict: that requires a separately merged harness and its own acceptance.

This fixture is frozen before implementation. Change its ground truth or thresholds only in a new explicitly reviewed evaluation generation, not to make an implementation pass.
