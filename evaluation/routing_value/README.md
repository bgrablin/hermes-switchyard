# Routing-value fixtures

These synthetic, civilian tasks test whether skill routing improves answers over an agent with the plugin off. A hidden label occurs only in the body of its target skill, not in the task prompt or the skill index. This is an offline fixture set, not a measured routing result.

## Use with the paired harness

`tasks.json` is a list of `switchyard-eval-task/1` records. A representative record has this shape:

```json
{
  "schema": "switchyard-eval-task/1",
  "id": "rv-001",
  "prompt": "...",
  "skills_dir": "catalogs/c25",
  "toolsets": ["skills"],
  "category": "hidden_fact",
  "expected_skill": "seed-swap-inventory",
  "checker": {"kind": "all_terms", "terms": ["<hidden label>"], "forbid_terms": []}
}
```

`skills_dir` is relative to this directory and contains a `skills/` tree. The harness copies that tree to the throwaway Hermes home's `skills/` directory for each turn. Match a task by `(skills_dir, id)`: each ID has the same prompt, checker and hidden facts at all three sizes (25, 150, 600). Names in `expected_skill` are bare, globally unique skill names. For `multi_skill` only, `expected_skill` is an **ordered two-name array**; its two `checker.terms` correspond to the names in order. All other tasks use a single name or `null`.

The shared checker contract supports `all_terms` (case-insensitive answer substrings), `exact` (the requested complete answer), and `regex` (a pattern); `forbid_terms` is an additional case-insensitive exclusion on any checker, not a standalone kind. These fixtures use `all_terms` for hidden facts and `exact` plus `forbid_terms` for no-skill cases. An answer without either required invented label cannot pass a hidden-fact or multi-skill task. A no-skill answer is required to be exact and must not include a catalog fact. The no-skill **false-load rate** comes from the skill-call trace; the final answer alone cannot prove that no skill was loaded.

The categories are 20 hidden-fact, 8 no-skill, 8 ambiguous near-neighbor, and 4 two-skill tasks per catalog. The Garden Walk cluster has eight similar skills with different logistical subjects. Only a skill body carries its subject's invented label.

Regenerate and validate in an environment with Hermes' skill parser available:

```sh
python evaluation/routing_value/generate_catalogs.py
python evaluation/routing_value/validate_fixtures.py
python -m unittest discover -s tests -p test_routing_value_fixtures.py -v
```

The validator uses Hermes' own discovery and frontmatter parser, checks each label's ownership and prompt absence, and compares every generated byte with a fresh temporary regeneration. It prints a receipt with category counts and SHA-256 hashes of each catalog and `tasks.json`; `--receipt` can also save this receipt **outside** the repository.

A future SHIP verdict requires routing-on to beat plugin-off on hidden-fact and ambiguous answer accuracy with no higher no-skill false-load rate, and with latency and cost no worse. Evaluate paired arms on a frozen plan and read actual tool traces and answers. Fixture validity alone gives no SHIP verdict.
