# Frozen offline outcome-label evaluation (issue #167)

This plan and `fixtures.json` are committed before generator or test code. The fixtures are synthetic; no retained user store, provider, Jev, or runtime hook is exercised. Baseline: the existing `receipt-history.jsonl` contains canonical routing receipts with session and turn IDs, not tool traces, next-user messages, or completion evidence. A routing selection, a receipt write, `verified: false`, and skill adoption do not establish answer quality or task completion.

## Input and attribution contract

- The offline generator takes validated, ordered retained receipt-history records and a separately supplied **ephemeral, local-only** evidence list keyed by `(session_id, turn_id)`. The evidence is not written by this change. It may hold a closed `turn_completed` boolean, `tool_trace_complete` boolean, closed `ok|error` events bound to the same session/turn, an assistant message ID, and the next turn's user message in memory. Optional `retried`/`undone` flags and typed reactions are censoring/non-evidence only. It must reject extra evidence fields, including raw error fields and chat IDs. No real-store replay is authorized by this evaluation.
- Only a unique, validated `(session_id, turn_id)` is attributable. Missing or duplicate keys censor all four labels. Bad or truncated receipt-history lines are omitted by the existing reader and **cannot** be reconstructed; report denominators for retained valid records only. A partial/rotated history tail never makes an absent following message a negative correction.
- `skill_loaded_after_selection` is true only for a selected skill with canonical consumer status `loaded`, `skill_load_verified: true`, and exact `loaded_skill == selected`. It is false only for a selected skill with canonical `load_failed`; no selection, advisory delivery, missing consumer evidence, or mismatched loaded skill is UNKNOWN. It is not answer quality.
- `tool_error_in_turn` is true if an attributable closed-status tool event is `error`; it is false only for a declared complete, same-turn trace with no errors. Missing trace or any mismatched/malformed event is UNKNOWN. A failed attempt followed by a successful retry still contains a tool error.
- `turn_completed` uses only an explicit boolean from the matching turn's external evidence. No receipt field or subsequent turn implies completion. Missing or malformed evidence is UNKNOWN.
- `next_turn_user_correction` is true only when the current turn was explicitly completed, the immediately following retained record belongs to the same session **and the same offline split**, its user message replies to the current assistant message ID, there is no retry/undo ambiguity, and the text begins (case-insensitively) with `No, I asked for`, `No, I asked you to`, `That's not what I asked for`, `That's not what I asked you to`, or `You misread/misunderstood my request`. It is false only for a complete, attributable next-user message with none of those markers and none of the ambiguous `retry`, `undo`, `try again`, `I meant`, or `actually` cues. Otherwise UNKNOWN. This is an **explicit correction-marker heuristic**, not correctness, satisfaction, or a claim that no unstated correction exists. Reactions, including wrong-message reactions, never set it.

## Closed output, split, and privacy

Every output label has exactly four `true|false|"UNKNOWN"` fields plus one `"train"|"holdout"|"UNKNOWN"` split enum; booleans are not strings. The surrounding report has the fixed `switchyard-outcome-label/1` schema name, aggregate per-field labeled/unknown counts and denominator (all retained valid records), and train/holdout/unknown counts. It includes no session/turn/message/chat IDs, text, prompts, paths, raw errors, reaction payloads, or cross-session identity. An output file must not be written on schema/privacy/leakage failure.

The fixed **offline-only** 20% split is `sha256(UTF-8("switchyard-outcome-label/1|holdout-v1|" + turn_id))`; take the first eight digest bytes as an unsigned big-endian integer. Remainder modulo 5 equal to zero is `holdout`; otherwise `train`. Missing/duplicate IDs get `UNKNOWN`. Turn IDs are never emitted. Repeated input runs must produce byte-identical labels and splits. The split assigns already-retained data for offline tuning only; it does **not** disable, alter, or compare runtime skill/effort hooks and creates no on-device arm.

## Frozen synthetic failures and thresholds

`fixtures.json` plants independent expected labels for selected/load-failed/advisory turns; tool errors and successful retries; explicit correction and harmless next message; missing/duplicate IDs; missing, mismatched, retried, or undone following turns; wrong-target reaction; partial/rotated tail; and train/holdout contamination. The test compares **literal expected labels** rather than reusing the implementation's predicate or hash helper. It verifies the frozen split examples (`a-correction` holdout, `b-no-correction` train), deterministic repetition, no train/holdout overlap, aggregate counts, and that synthetic user-text/privacy markers never occur in output.

**Ship gate for this offline slice:** zero known false-positive correction labels in the frozen cases; at most 5% disagreement among independently planted, attributable true/false field values (denominator and rate reported, not rounded down); zero train/holdout overlap; stable repeated assignment; all expected unknowns preserved; no forbidden output or schema expansion. Kill on leakage, invented labels, a privacy violation, or an unsupported benefit claim. The comparative SHIP verdict waits for the merged harness and any production benefit claim requires at least 100 eligible attributable turns **per arm** plus predeclared paired error/correction, cost, denominator and interval analysis. This offline slice cannot establish benefit and does not run on a real store without master authorization.
